# Guide: Passing Table Names in Hibernate

This guide explains how to specify custom table names in Hibernate/JPA applications.

## Problem Statement

By default, Hibernate uses the entity class name as the database table name. However, in many real-world scenarios, you need to:
- Use a different table name than the entity class name
- Specify the schema for the table
- Work with existing database schemas

## Solution Overview

Hibernate provides the `@Table` annotation to specify custom table names and related metadata.

## Methods to Pass Table Names

### 1. Basic Table Name Specification

Use the `@Table` annotation with the `name` attribute:

```java
@Entity
@Table(name = "users")
public class User {
    // Entity fields
}
```

**Result:** The `User` entity will map to a database table named `users` instead of `User`.

**Example Location:** See `src/main/java/com/example/jap1/entity/User.java`

### 2. Table Name with Schema

Specify both table name and schema:

```java
@Entity
@Table(name = "products", schema = "inventory")
public class Product {
    // Entity fields
}
```

**Result:** The `Product` entity will map to `inventory.products` table.

**Example Location:** See `src/main/java/com/example/jap1/entity/Product.java`

### 3. Table Name with Catalog and Schema (Advanced)

For databases that support catalogs:

```java
@Entity
@Table(
    name = "table_name",
    catalog = "catalog_name",
    schema = "schema_name"
)
public class MyEntity {
    // Entity fields
}
```

### 4. Additional @Table Attributes

The `@Table` annotation supports several other attributes:

```java
@Entity
@Table(
    name = "users",
    schema = "public",
    catalog = "mydb",
    uniqueConstraints = {
        @UniqueConstraint(columnNames = {"email"})
    },
    indexes = {
        @Index(name = "idx_username", columnList = "user_name")
    }
)
public class User {
    // Entity fields
}
```

## Column Name Mapping

Along with table names, you can also customize column names:

```java
@Column(name = "user_name", nullable = false, length = 100)
private String userName;

@Column(name = "email", unique = true)
private String email;
```

## Configuration for Schema Creation

When using schemas, ensure your database configuration supports schema creation:

```properties
# For H2 Database
spring.datasource.url=jdbc:h2:mem:testdb;INIT=CREATE SCHEMA IF NOT EXISTS INVENTORY

# For PostgreSQL
spring.datasource.url=jdbc:postgresql://localhost:5432/mydb?currentSchema=myschema

# For MySQL
spring.datasource.url=jdbc:mysql://localhost:3306/mydb?createDatabaseIfNotExist=true
```

## Best Practices

1. **Use lowercase table names:** Many databases are case-sensitive. Using lowercase avoids issues.

2. **Plural names for tables:** Common convention is to use plural names for tables (e.g., `users`, `products`).

3. **Snake_case for column names:** Use underscores to separate words (e.g., `user_name`, `product_name`).

4. **Schema separation:** Use schemas to organize tables by domain or module (e.g., `inventory`, `user_management`, `reporting`).

5. **Explicit naming:** Always specify table and column names explicitly rather than relying on defaults for better control and clarity.

## Database-Specific Considerations

### H2 (In-Memory)
- Requires schema creation in the JDBC URL: `INIT=CREATE SCHEMA IF NOT EXISTS INVENTORY`
- Schemas are case-sensitive in H2

### PostgreSQL
- Default schema is `public`
- Schemas must be created before use or specified in connection URL
- Supports full catalog/schema hierarchy

### MySQL
- Uses databases instead of schemas
- Schema and catalog are often equivalent in MySQL

### Oracle
- Schema is tied to the user
- Each user has their own schema by default

## Common Issues and Solutions

### Issue 1: Schema not found
**Problem:** `Schema "INVENTORY" not found`

**Solution:** Configure database to create schema automatically:
```properties
spring.datasource.url=jdbc:h2:mem:testdb;INIT=CREATE SCHEMA IF NOT EXISTS INVENTORY
```

### Issue 2: Table name conflicts
**Problem:** Multiple entities trying to use the same default table name

**Solution:** Always specify explicit table names:
```java
@Table(name = "unique_table_name")
```

### Issue 3: Case sensitivity
**Problem:** Table found in database but Hibernate can't access it

**Solution:** Match the case used in the database:
```java
@Table(name = "USERS") // If database has uppercase table names
```

## Summary

The `@Table` annotation is the primary mechanism for controlling table names in Hibernate:
- Use `name` attribute for custom table names
- Use `schema` attribute for schema specification
- Use `catalog` attribute for catalog specification (when needed)
- Combine with `@Column` for complete control over database mapping

This project provides working examples of these concepts with a fully functional REST API.
